# The Cadence website (cadence.corvexsa.com)

A static site. No build step, no dependencies, nothing to install — the files in this folder are
exactly what gets served. Open `index.html` in a browser to work on it, or serve the folder:

```bash
npx serve site          # or: python -m http.server 8080 -d site
```

Deployed to GitHub Pages from the `gh-pages` branch (see "Deploying" in the root README), live at
<https://cadence.corvexsa.com/>. The domain comes from the `CNAME` file in this folder (it must
contain exactly `cadence.corvexsa.com`); GitHub Pages redirects the old
`alycoulibal2-sketch.github.io/Cadence-Animator/…` addresses to it, which is what keeps the links
already inside shipped apps working. Every link on the site is relative; every canonical / `og:url`
/ sitemap URL uses the domain. If it ever changes, change `CNAME`, `sitemap.xml`, `robots.txt` and
each page's `<head>`.

The brand is **Cadence by Corvexsa**: Corvexsa is the company, Cadence one of its tools. The header
carries the Cadence mark, "Cadence" and a small "by Corvexsa"; the footer says "Cadence is a
Corvexsa tool · © 2026 Corvexsa". The look follows the Cadence AI design spec
(`CadenceAI/design/SPEC-design.md`) and the approved boards W1-Home, W2-Pricing and W3-Parents.

## Update the site on every release

**This is part of cutting a release, not an afterthought.** The site states the version, the file
sizes, the checksums, the VirusTotal links and a lot of exact counts; every one of those goes stale
on its own.

After `npm run release` succeeds and the GitHub release is live:

1. **Regenerate the shortcut reference** — reads `renderer/js/app.js` and rewrites the generated
   block in `docs.html`, refreshing the shortcut and command counts quoted in the prose.

   ```bash
   node site/tools/gen-shortcuts.js
   ```

2. **Refresh the release facts** — version, filenames, sizes, SHA-256 and VirusTotal links for both
   builds, on `index.html`, `docs.html` and `safety.html`.

   ```bash
   node site/tools/sync-release.js          # reads the live GitHub release
   node site/tools/sync-release.js --check  # just report drift, change nothing
   ```

3. **Regenerate the changelog** — the last 60 commits from `git log`, grouped by day, each linked
   to its commit. The whole page is produced by the script; there is nothing to hand-edit.

   ```bash
   node site/tools/gen-changelog.js              # rewrite site/changelog.html
   node site/tools/gen-changelog.js --count 80   # a different window
   ```

4. **Write the new features in.** No script can do this one. If the release added a capability,
   it belongs in `index.html`'s feature grid (`#features`) and the relevant `docs.html` section.
   If it added something countable, re-count it from source — never copy a number out of a
   changelog or a comment. When Cadence AI ships, the "Coming soon" labels come off in the same
   pass (see "Placeholders" below).

5. **Check every page headlessly** — console errors, horizontal overflow, broken images, and a
   full-page screenshot of every page at 360, 820 and 1366 px (plus the light theme).

   ```bash
   node node_modules/electron/cli.js site/tools/check-site.js
   ```

6. **Re-read anything you changed with fresh eyes**, then commit and deploy (root README).

### What the scripts rewrite

`sync-release.js` finds these and nothing else — keep them intact when editing markup:

| Element | Meaning |
|---|---|
| `<span data-version>…</span>` | the version, everywhere it is shown |
| `<a … href="…" … data-dl="installer">` / `data-dl="portable"` | download links (`href` must come before `data-dl`) |
| `<span data-size>…</span>` | installer size in the hero and CTA buttons |
| `<dd data-size-installer>…</dd>`, `<dd data-size-portable>…</dd>`, `<span data-size-…>` | sizes on the cards |
| `<code data-file="installer">…</code>`, `<span data-file="…">` | filenames as text (cards, SmartScreen mock, verifier, PowerShell line) |
| `<details class="hash" data-build="…"><summary>Verify this file (SHA-256)</summary><code>HEX</code>` | the two hashes per page, **in document order: installer then portable** |
| `<a … href="…" … data-vt="installer">` / `data-vt="portable"` | VirusTotal links (the hash is in the URL) |
| `<a … href="…" … data-release-tag>` | the "tagged on GitHub" link |

Sizes are written with a non-breaking space between the number and `MB`; `--check` compares
strings, so keep it that way. `gen-shortcuts.js` owns everything between `SHORTCUTS:BEGIN` and
`SHORTCUTS:END` in `docs.html`, plus the `Filter N shortcuts…` placeholder and the "all N commands"
sentence. `gen-changelog.js` owns all of `changelog.html`.

`site.js` also retargets the same elements at a *newer* release if one exists when the page loads;
it never downgrades, and it blanks the hashes (`[data-stale-on-update]`) rather than show a stale one.

## Plans, payments and the licence API

**Payments are not open.** The paid plans are written into the HTML as "Opening soon" buttons that
link nowhere, and no page links to a checkout. The old one-time $9 / $12 Payment Links were removed
from the site and from `config.js`. Opening payments (the new Payment Links, the ask-a-parent
checkout, Manage plan) is a separate step that needs Aly's "go live" first
(`CadenceAI/design/research/money.md` §12-13).

`assets/js/config.js` holds two strings; an **empty string means "not open yet"**:

| Key | Used by | Empty means |
|---|---|---|
| `LICENSE_API` | the Founders count, `account.html`, `thanks.html` | the count stays "First 100 only"; account and thanks say checks aren't connected |
| `SUPPORT_EMAIL` | every contact line (`[data-support]`) | the pages show the placeholder `[SUPPORT EMAIL]`. Only ever a Corvexsa address, never a personal one |

The licence API contract (all `GET`, JSON). **The service must list the site's origin,
`https://cadence.corvexsa.com`, in its `ALLOWED_ORIGINS`,** or the browser blocks every answer:

```
/stats                v2: { founders: { sold, limit, left }, founding? }      v1: { founding: { sold, limit } }
/verify?email=&key=   v2: { valid, tier: founder|pro|studio, plan, seat, seats, renews, paid_until,
                            since, checked, reason?, message? }                v1: { valid, tier: "pro", since }
/license?session_id=  v2: { key, email, tier, plan, seatKeys? (Studio), paid_until, ... }   v1: { key, email }
```

The pages read both. A v1 answer (no `plan`, no `paid_until`) can only have come from the old
one-time links, so it is shown as **Founder · Pro forever**. The Founders count on `pricing.html`
renders only from a v2 `founders` figure; the old `founding` counter is a different thing and is
never shown. Stripe's success URL is `…/thanks.html?session_id={CHECKOUT_SESSION_ID}`.

The app's "Ask a parent" link is `{SITE}/parent.html?plan=<plan>&c=<code>` (`src/pro.js`; the
setting `pro.site` overrides the site). While payments are closed, `parents.html#ask` shows the plan
that was asked for, the random code, and "Payments open soon — nothing to do yet".

### Placeholders the owner still has to fill

- `SUPPORT_EMAIL` in `assets/js/config.js`: a Corvexsa support address (until then every contact
  line reads `[SUPPORT EMAIL]`);
- Cadence AI: every part of it on `index.html`, `pricing.html` and `parents.html` says "Coming
  soon", and the preview pictures are labelled drawings. When it ships, replace the drawings with
  clips recorded from the app, drop the labels, and give it a network row on `safety.html` and a
  present-tense line on `privacy.html`;
- the code-signing certificate — the SmartScreen panel, the safety page and the FAQ all say
  releases are unsigned; when they are signed, rewrite those three places.

### Re-capture the hero screenshot

The hero (`assets/img/hero-animator.png`, also the `og:image`; `hero-animator.webp` is the same
pixels, lossless) is a real screenshot of the app at 1920 x 1020, taken at a 2x device scale so the
UI reads at the size the page shows it. Re-take it whenever the app's chrome changes (the title bar,
the toolbar, the panel layout), then regenerate the WebP:

```bash
npx electron . --user-data-dir=test-output/hero-ud --force-device-scale-factor=2 --window-size=960x510 \
  --screenshot=site/assets/img/hero-animator.png --demo-js-file=site/tools/capture-hero.js
```

`--window-size` pins the page size and is honoured only on `--screenshot` runs (see `createWindow`
in `src/main.js`). Look at the result before committing it.

The favicons (`favicon.svg`, `favicon.ico`, `apple-touch-icon.png`) are generated from `../brand/` by
`npm run brand` — never hand-edit them.

## Verifying counts

Every number on this site was counted from source, not estimated. Run from the repo root:

```bash
node -e "console.log(require('./package.json').version)"                                # version
grep -c 'server\.tool(' mcp-server/index.js                                              # MCP tools
node -e "const s=require('fs').readFileSync('renderer/js/app.js','utf8');console.log((s.match(/\n\s*C\(\{/g)||[]).length)"   # palette commands
node site/tools/gen-shortcuts.js --check                                                 # shortcuts (prints the count)
node --input-type=module -e "const R=await import('./renderer/js/pnx/registry.js');await import('./renderer/js/pnx/nodes/index.js');console.log(R.nodeCount(), Object.keys(R.nodesByCategory()).length)"   # node types, categories with nodes
node --input-type=module -e "const E=await import('./renderer/js/easing.js');console.log(E.STYLES.length, E.DIRECTIONS.length)"   # easing styles × directions
node --input-type=module -e "const P=await import('./renderer/js/propTracks.js');console.log(P.CLASS_NAMES.length, P.ACTION_KEYS.length, Object.keys(P.VALUE_TYPES).length)"   # classes, actions, value types
node --input-type=module -e "const m=await import('./renderer/js/effectModel.js');console.log(Object.keys(m.LAYER_TYPES).length, Object.keys(m.MODIFIER_TYPES).length)"   # layer types, modifiers
node --input-type=module -e "const l=await import('./renderer/js/effectLibrary.js');console.log(l.EFFECT_ARCHETYPES.length)"   # archetypes
node --input-type=module -e "const p=await import('./renderer/js/particleLibrary.js');console.log(p.PARTICLE_PRESETS.length)"   # particle presets
node -e "console.log((require('fs').readFileSync('test/smoketest.js','utf8').match(/await step\(/g)||[]).length)"   # smoke-test checks
```

Modules that import `state.js` cannot be loaded in plain Node — `state.js` touches
`window.cadence` at module load — so count those with a regex over the source instead of an import.

`site.js` can still show live GitHub numbers on any element carrying `data-gh` (stars, forks,
downloads, commits, last release); no page uses them at the moment. Downloads would sum the
`download_count` of every `.exe` asset across all releases, leaving out the `.blockmap` and
`latest.yml` assets the updater fetches on every launch.

## Ground rules

- **Nothing on this site may be aspirational.** If a feature is early, partial, coming, or excluded
  from export, the page says so in the same sentence. Cadence AI and the paid plans are "Coming
  soon" / "Opening soon" everywhere they appear, until they ship.
- **No fabricated proof.** No testimonials, reviews, counters, countdowns or scarcity that is not
  literally true (the FTC's consumer-review rule covers fake social-proof indicators). The only
  scarcity is the Founders cohort ("first 100"), and its live count renders only from the licence API.
- **No personal email address anywhere on the site.** Contact lines use `SUPPORT_EMAIL`, which is
  only ever a Corvexsa address.
- **Do not state the maker's name or age anywhere on the site.**
- **Third-party requests, complete list:** Google Fonts (one stylesheet; the Inter file is fetched
  only where Segoe UI is missing), the GitHub API (the latest release), and Cadence's licence API
  (the Founders count on the pricing page; key checks on account and thanks, when used), and
  Cadence's own anonymous counter (`assets/js/stats.js` -> `services/stats/` on main): visits, time
  on screen, buy-button (`data-buy`) and download (`data-dl`) clicks. No cookies, no names, no IPs.
  Keep `data-buy` on every plan button when payments open, or its clicks stop counting. The
  private totals are at `stats.html` (key in `cadence-stats-key.txt`). No outside analytics, no CDN scripts. The SHA-256 verifier runs entirely in the browser.
- **Downloads work with JavaScript off.** The hardcoded `href`s are the source of truth; `site.js`
  only ever retargets them at a *newer* release, never an older one. Every "not open yet" state is
  written in the HTML; scripts only ever upgrade it.
- **The design system is the app's.** `assets/css/site.css` restates the app's tokens as the Cadence
  AI design spec lists them ("Cadence Dark" + periwinkle, and "Light"); type is Segoe UI, then Inter.
  Calm by rule: no gradient washes, no glow blobs, no left-border cards. If the app's palette
  changes, change both.
- **Dark first, light for real.** `prefers-color-scheme` picks the theme; the toggle in the header
  overrides it and remembers the choice in `localStorage` (`cadence-theme`), applied before first
  paint by the inline script in each `<head>`.
- **Every page shares one header and footer.** When you change one, change all eleven pages
  (`gen-changelog.js` carries its own copy — change it there too).
