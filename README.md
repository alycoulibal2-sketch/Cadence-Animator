# The Cadence Animator website

A static site. No build step, no dependencies, nothing to install — the files in this folder are
exactly what gets served. Open `index.html` in a browser to work on it, or serve the folder:

```bash
npx serve site          # or: python -m http.server 8080 -d site
```

Deployed to GitHub Pages from the `gh-pages` branch (see "Deploying" in the root README), live at
<https://alycoulibal2-sketch.github.io/Cadence-Animator/>. There is no custom domain yet, so every
link on the site is relative and every canonical / `og:url` / sitemap URL uses that address. When a
domain lands, change the base URL in `sitemap.xml`, `robots.txt` and each page's `<head>`.

```
site/
  index.html            landing page, in the researched order: promise → demo → price anchor →
                        live proof → three outcomes → download + SmartScreen → safety → pricing →
                        FAQ → roadmap
  docs.html             documentation — install through troubleshooting, the generated shortcut
                        reference, "What the engine gained", "Pro and your licence key"
  safety.html           the safety proofs in full: sources, network table, files, CSP, the
                        SHA-256 verifier, VirusTotal links, how to report
  changelog.html        GENERATED by tools/gen-changelog.js from git log — never hand-edit
  account.html          email + key → licence API verify (noindex)
  thanks.html           Stripe return page: fetches the key by session_id (noindex)
  privacy.html          ten lines
  assets/css/site.css   the whole design system (the app's palette, dark + light)
  assets/js/config.js   THE ONLY FILE TO EDIT TO SWITCH PRO ON (see below)
  assets/js/site.js     theme, nav, palette, live GitHub numbers, hash verifier, Pro wiring
  assets/img/           hero still (PNG + lossless WebP of the same pixels), favicon
  tools/                the scripts that keep the site honest (below)
```

## Update the site on every release

**This is part of cutting a release, not an afterthought.** The site states the version, the file
sizes, the checksums, the VirusTotal links and a lot of exact counts; every one of those goes stale
on its own.

After `npm run release` succeeds and the GitHub release is live:

1. **Regenerate the shortcut reference** — reads `renderer/js/app.js` and rewrites the generated
   block in `docs.html`, refreshing the shortcut and command counts quoted in the prose.

   ```bash
   node site/tools/gen-shortcuts.js
   ```

2. **Refresh the release facts** — version, filenames, sizes, SHA-256 and VirusTotal links for both
   builds, on `index.html`, `docs.html` and `safety.html`.

   ```bash
   node site/tools/sync-release.js          # reads the live GitHub release
   node site/tools/sync-release.js --check  # just report drift, change nothing
   ```

3. **Regenerate the changelog** — the last 60 commits from `git log`, grouped by day, each linked
   to its commit. The whole page is produced by the script; there is nothing to hand-edit.

   ```bash
   node site/tools/gen-changelog.js              # rewrite site/changelog.html
   node site/tools/gen-changelog.js --count 80   # a different window
   ```

4. **Write the new features in.** No script can do this one. If the release added a capability,
   it belongs in `index.html`'s outcome sections, the roadmap (move a row from "Next" to "Done"
   or delete it), and the relevant `docs.html` section. If it added something countable, re-count
   it from source — never copy a number out of a changelog or a comment. The "What the engine
   gained" section of the docs says those features "ship with the next release": when they ship,
   rewrite that sentence.

5. **Check every page headlessly** — console errors, horizontal overflow, broken images, and a
   full-page screenshot of every page at 360, 820 and 1366 px (plus the light theme).

   ```bash
   node node_modules/electron/cli.js site/tools/check-site.js
   ```

6. **Re-read anything you changed with fresh eyes**, then commit and deploy (root README).

### What the scripts rewrite

`sync-release.js` finds these and nothing else — keep them intact when editing markup:

| Element | Meaning |
|---|---|
| `<span data-version>…</span>` | the version, everywhere it is shown |
| `<a … href="…" … data-dl="installer">` / `data-dl="portable"` | download links (`href` must come before `data-dl`) |
| `<span data-size>…</span>` | installer size in the hero and CTA buttons |
| `<dd data-size-installer>…</dd>`, `<dd data-size-portable>…</dd>`, `<span data-size-…>` | sizes on the cards |
| `<code data-file="installer">…</code>`, `<span data-file="…">` | filenames as text (cards, SmartScreen mock, verifier, PowerShell line) |
| `<details class="hash" data-build="…"><summary>Verify this file (SHA-256)</summary><code>HEX</code>` | the two hashes per page, **in document order: installer then portable** |
| `<a … href="…" … data-vt="installer">` / `data-vt="portable"` | VirusTotal links (the hash is in the URL) |
| `<a … href="…" … data-release-tag>` | the "tagged on GitHub" link |

Sizes are written with a non-breaking space between the number and `MB`; `--check` compares
strings, so keep it that way. `gen-shortcuts.js` owns everything between `SHORTCUTS:BEGIN` and
`SHORTCUTS:END` in `docs.html`, plus the `Filter N shortcuts…` placeholder and the "all N commands"
sentence. `gen-changelog.js` owns all of `changelog.html`.

`site.js` also retargets the same elements at a *newer* release if one exists when the page loads;
it never downgrades, and it blanks the hashes (`[data-stale-on-update]`) rather than show a stale one.

## Switching Pro on

`assets/js/config.js` is the only file to edit. Every value is a string; an **empty string means
"not open yet"**, and the pages render an honest disabled state for it:

| Key | Used by | Empty means |
|---|---|---|
| `PRO_FOUNDING_LINK` | pricing card, founding button | "Pro is opening soon — join the GitHub watch list" (not a link) |
| `PRO_LINK` | pricing card, regular button | same |
| `LICENSE_API` | founding counter, `account.html`, `thanks.html` | counter hidden; account and thanks pages say verification opens with Pro |
| `SUPPORT_EMAIL` | account / thanks error states | they point at the GitHub issue tracker instead |

The licence API contract the pages expect (all `GET`, JSON, CORS-enabled for the site's origin):

```
{LICENSE_API}/stats                     -> { "founding": { "sold": 12, "limit": 100 } }
{LICENSE_API}/verify?email=&key=        -> { "valid": true|false, "tier": "pro", "since": "2026-09-06" }
{LICENSE_API}/license?session_id=       -> { "key": "XXXX-…", "email": "…" }
```

The founding counter ("N of 100 founding keys left") only renders when `/stats` answers with both
numbers; anything else and it stays hidden. Stripe's success URL should be
`…/thanks.html?session_id={CHECKOUT_SESSION_ID}`.

### Placeholders the owner still has to fill

- the four values in `assets/js/config.js` (above);
- the 20–40 s demo loop: the `#demo` block is a labelled "video coming" poster on purpose — when
  the video exists, replace the poster's play affordance with a `<video>` (poster = the same still,
  `muted loop playsinline preload="metadata"`, under 2 MB), and delete the "video coming" chip;
- the custom domain, when there is one (see the top of this file);
- the code-signing certificate — the SmartScreen panel, the safety page and the FAQ all say
  releases are unsigned; when they are signed, rewrite those three places.

## Verifying counts

Every number on this site was counted from source, not estimated. Run from the repo root:

```bash
node -e "console.log(require('./package.json').version)"                                # version
grep -c 'server\.tool(' mcp-server/index.js                                              # MCP tools
node -e "const s=require('fs').readFileSync('renderer/js/app.js','utf8');console.log((s.match(/\n\s*C\(\{/g)||[]).length)"   # palette commands
node site/tools/gen-shortcuts.js --check                                                 # shortcuts (prints the count)
node --input-type=module -e "const R=await import('./renderer/js/pnx/registry.js');await import('./renderer/js/pnx/nodes/index.js');console.log(R.nodeCount(), Object.keys(R.nodesByCategory()).length)"   # node types, categories with nodes
node --input-type=module -e "const E=await import('./renderer/js/easing.js');console.log(E.STYLES.length, E.DIRECTIONS.length)"   # easing styles × directions
node --input-type=module -e "const P=await import('./renderer/js/propTracks.js');console.log(P.CLASS_NAMES.length, P.ACTION_KEYS.length, Object.keys(P.VALUE_TYPES).length)"   # classes, actions, value types
node --input-type=module -e "const m=await import('./renderer/js/effectModel.js');console.log(Object.keys(m.LAYER_TYPES).length, Object.keys(m.MODIFIER_TYPES).length)"   # layer types, modifiers
node --input-type=module -e "const l=await import('./renderer/js/effectLibrary.js');console.log(l.EFFECT_ARCHETYPES.length)"   # archetypes
node --input-type=module -e "const p=await import('./renderer/js/particleLibrary.js');console.log(p.PARTICLE_PRESETS.length)"   # particle presets
node -e "console.log((require('fs').readFileSync('test/smoketest.js','utf8').match(/await step\(/g)||[]).length)"   # smoke-test checks
```

Modules that import `state.js` cannot be loaded in plain Node — `state.js` touches
`window.cadence` at module load — so count those with a regex over the source instead of an import.

The proof strip (stars, forks, downloads, commits, last release) is **not** counted here: `site.js`
fetches it from the GitHub API on every page view and shows "—" until it arrives. Downloads sum the
`download_count` of every `.exe` asset across all releases; the `.blockmap` and `latest.yml` assets
are excluded because the updater fetches them on every launch.

## Ground rules

- **Nothing on this site may be aspirational.** If a feature is early, partial, coming, or excluded
  from export, the page says so in the same sentence. The Effect Sheet is "coming in the next
  release"; flocking and events are "built, ships next"; fire, smoke and volumes are "roadmap".
- **No fabricated proof.** No testimonials, reviews, counters, countdowns or scarcity that is not
  literally true (the FTC's consumer-review rule covers fake social-proof indicators). The only
  scarcity is the numbered founding cohort, and its counter renders only from the licence API.
- **Do not state the maker's name or age anywhere on the site.**
- **Third-party requests, complete list:** Google Fonts (one stylesheet, two families), the GitHub
  API (numbers and the latest release), and — only once configured — the owner's licence API.
  No analytics, no trackers, no CDN scripts. The SHA-256 verifier runs entirely in the browser.
- **Downloads work with JavaScript off.** The hardcoded `href`s are the source of truth; `site.js`
  only ever retargets them at a *newer* release, never an older one. Every "not open yet" state is
  written in the HTML; scripts only ever upgrade it.
- **The design system is the app's.** `assets/css/site.css` restates `renderer/js/themes.js`
  ("Cadence Dark" and "Light"). If the app's palette changes, change both.
- **Dark first, light for real.** `prefers-color-scheme` picks the theme; the toggle in the header
  overrides it and remembers the choice in `localStorage` (`cadence-theme`), applied before first
  paint by the inline script in each `<head>`.
- **Every page shares one header and footer.** When you change one, change all seven pages
  (`gen-changelog.js` carries its own copy — change it there too).
