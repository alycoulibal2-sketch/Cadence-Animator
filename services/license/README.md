# Cadence Animator Pro — licence service

The smallest thing that makes "pay once, get a key, the key unlocks Pro" true without a database:

- a **key** is `HMAC-SHA256(LICENSE_SECRET, lower-cased email)` rendered as `XXXX-XXXX-XXXX-XXXX-XXXX`
  (base-32, no `0/O/1/I`). Nothing is stored — a key is valid exactly when it is the HMAC of its email;
- a key is only **issued** (`/license`) after Stripe confirms the Checkout Session it came from was
  paid on one of *our* payment links;
- **verification** (`/verify`) re-checks Stripe for a paid, unrefunded session under that email, so a
  refund stops the key verifying. If Stripe is unreachable the HMAC alone answers and the response says
  `"checked": "offline"`.

Node 18+, zero dependencies, ~200 lines: `server.js`. Tests: `node test.js` (no network).

## Endpoints (all GET, JSON, CORS for the site's origin)

```
/health                              { ok: true }
/stats                               { founding: { sold, limit } }          cached 60 s
/license?session_id=cs_…             { key, email }                         402 if not a paid purchase on our links
/verify?email=&key=                  { valid, tier: "pro", since, checked } valid:false with a reason when refunded
```

These are exactly what `site/assets/js/config.js` (`LICENSE_API`) and the desktop app (`src/pro.js`)
expect. Rate limit: 60 requests per minute per IP. Nothing personal is logged.

## Environment

| Variable | What |
| --- | --- |
| `STRIPE_SECRET_KEY` | the **restricted** key described below — never the full secret key |
| `LICENSE_SECRET` | 32+ random characters. Changing it invalidates every key ever issued. Back it up. |
| `FOUNDING_PAYMENT_LINK` | `plink_…` of the founding price (first 100) |
| `PRO_PAYMENT_LINK` | `plink_…` of the regular price |
| `FOUNDING_LIMIT` | `100` |
| `ALLOWED_ORIGINS` | comma-separated, e.g. `https://<user>.github.io` — the site's origin. Empty reflects any origin (development only). |
| `PORT` | set by Render |

**Restricted Stripe key.** In Stripe → Developers → API keys → *Create restricted key*: Checkout
Sessions **Read**, PaymentIntents **Read**, Charges **Read**. Nothing else. The service only ever reads.

## Set up, in order (about fifteen minutes, all in the owner's own accounts)

1. **Stripe products, prices and payment links** — one command, run from this folder with the account's
   *full* secret key in the environment for this step only (it creates things; the service itself uses
   the read-only key):

   ```bash
   STRIPE_SECRET_KEY=sk_live_… SITE_URL=https://<user>.github.io/CadenceAnimator node tools/setup-stripe.mjs
   ```

   It creates (or finds, if run twice) the product **Cadence Animator Pro**, a **$9 founding** one-time
   price limited to 100 completed checkouts, a **$12** regular price, and two payment links that return
   the buyer to `SITE_URL/thanks.html?session_id={CHECKOUT_SESSION_ID}`. It prints the two `plink_…`
   ids and URLs. Add `--dry-run` to see what it would do.

2. **Deploy this service** — the repo's root `render.yaml` describes it (Render Blueprint: New → Blueprint
   → this repo). Fill the four `sync: false` variables in the Render dashboard. `LICENSE_SECRET` is
   generated by Render; copy it somewhere safe.

   Free plan note: the instance sleeps after 15 minutes idle and takes ~30 s to wake. The site's
   founding counter simply stays hidden until it answers; the desktop app waits up to 20 s and says
   "the licence server is waking up, try again" rather than failing.

3. **Switch the site on** — in `site/assets/js/config.js` set `PRO_FOUNDING_LINK`, `PRO_LINK` (the
   payment-link URLs), `LICENSE_API` (the Render URL, no trailing slash) and `SUPPORT_EMAIL`. Redeploy
   the site.

4. **Point the app at it** — `src/pro.js`, `DEFAULT_LICENSE_API`. Ship a release.

## What a buyer experiences

Pricing card → Stripe Checkout (Stripe's page, card details never touch our site) → back to
`thanks.html`, which calls `/license?session_id=` and shows the key → the app's *Cadence Pro* dialog
(email + key) calls `/verify`, stores the key locally, and re-verifies quietly every 7 days with a
30-day offline grace. Lost key: `account.html` re-derives nothing — it only verifies — so the buyer
re-opens their Stripe receipt link (`thanks.html?session_id=…`) or writes to `SUPPORT_EMAIL`, where
the owner can look the session up in the Stripe dashboard and run `/license` for them.

  finished thing", not as copy protection.
