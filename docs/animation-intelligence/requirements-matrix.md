## How to read a row

| Column | Meaning |
| --- | --- |
| **ID** | stable; never reused, never renumbered |
| **§** | directive section that is the source of the requirement |
| **Pri** | P0 foundation (something else is blocked on it) · P1 core product promise · P2 quality · P3 optional/specialised |
| **Status** | `unplanned` · `designed` (interface exists, behaviour does not) · `partial` (some of the requirement genuinely works; the Limits cell says which part does not) · `implemented` · `benchmarked` · `deferred` (with a stated dependency) · `blocked` |
| **Repr.** | the data representation that carries it |
| **Module** | primary owning module |
| **MCP** | tools / resources / workflows that expose it |
| **UI** | user-visible location, or `—` for model-facing only |
| **Tests** | what proves it |
| **Bench** | benchmark coverage (Part 59) |
| **Limits** | the honest caveat |

`Owner` is the animation-intelligence programme for every row below unless a row says otherwise.
`Version introduced` is recorded in the Status cell for anything past `designed`.

Status counts, this revision, counted from the table itself — **165 rows**:
**implemented 75 · partial 22 · designed 8 · deferred 2 · blocked 1 · unplanned 57.**
Nothing is `benchmarked`; no benchmark suite exists yet (BCH-001).

The delta from the previous revision (*implemented 72 · partial 17 · designed 8 · deferred 2 ·
blocked 1 · unplanned 65*) is Phase 5 and nothing else. **3 rows** moved to `implemented`
(MOT-003, MOT-004, MOT-008) and **5** to `partial` (MOT-005, MOT-007, MOT-009, MOT-010, EXP-002).
Counts are counted from the table below by script, not hand-written.

Phase 5 is the first phase in which this build measures MOTION rather than data or pixels. What it
deliberately did NOT do, so no row is read as more finished than it is:

* **13 of Part 23's 18 quantities are measured**, and the five that are not are enumerated in
  `ai/motion.js` `MEASUREMENTS` with what blocks each: screen-space velocity and acceleration (no
  active-camera model), tangent continuity (Cadence keys carry an easing style, not a tangent — so
  this one can never be measured, not merely not-yet), distance to an expected arc (no arc model),
  and comparison against a reference motion (nothing is ingested).
* **Nothing INFERS a contact.** Drift is measured against a ContactSpec somebody declared. A foot
  the animator meant to plant and never said so about is invisible to every check here, and
  `analyze_contacts` says so rather than guessing which foot was meant.
* **The contact point is the effector's own position on the contact's first frame.** Cadence has no
  ground plane and no collision surface, so there is nothing external to measure against. An
  effector that was already sliding when the contact was declared measures clean, and that
  assumption travels in the finding's own evidence.
* **3 of Part 23's 9 variation kinds can be told apart**, because a stepped key, a held pose and a
  marked impact each leave a mark in the project. The other six cannot, and an unexplained
  discontinuity comes back `unclassified` with the question attached — never as a defect. Part 23:
  "Never label motion as bad simply because it deviates from smoothness."
* **Angular speed is unsigned**, so a reversal and a continuation look alike. That is why MOT-015
  (counter-rotation, a direction relationship) did not move.
* **Nothing here judges.** Part 4.5: every number in `ai/motion.js` is a measurement, the ranking
  and the recommendation are in `ai/diagnose.js`, and a recommendation carries
  `requires_user_approval`.
* **2 of Part 46's 7 "why?" workflows run**, 2 are routed to `explain_change` (which answers them
  better, with pixels) and 3 are blocked. Weight, effect change and camera framing all need models
  that do not exist.

Carried forward and still true: the compiler EDITS rather than generates. MOT-008 shipped the
safety half of key insertion — an inserted key can now be checked against a declared contact — but
no strategy adds or removes one, so CMP-001 stays `partial`. A phase name is still evidence-bound.
8 of 15 motion dimensions and all 5 VFX dimensions still compile to nothing and are reported in
`blocked` rather than dropped; what changed is WHY: `contact_firmness` and `arc_smoothness` are now
blocked on the missing EDIT (an IK solve, a trajectory editor) rather than on the missing
measurement.

Phase 4's caveats are all still true and are not repeated here: 5 of Part 43's 24 observation kinds
exist, the passes see rig parts only, an object-ID pass measures visible pixels rather than motion,
a baseline stores digests rather than pixels, and nothing is compared across two viewpoints.
`can_fully_validate` remains false — contact drift LEFT its `unavailable` list this phase, and
perceptual comparison, depth ordering, temporal validation, undeclared contacts and balance remain.
